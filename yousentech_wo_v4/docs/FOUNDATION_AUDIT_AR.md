# تدقيق Foundation + Setup MVP

## المصدر والنطاق

أُعيد البناء من المصدر الرسمي الجديد، واقتصر النطاق على الأساس والتهيئة. شاشة
أمر التركيب وREST controllers غير منفذتين حتى اعتماد هذه المرحلة.

## الموانع التي عولجت

- إصلاح imports ونماذج الفيلم والأجزاء والأسعار والعمولات الناقصة.
- فصل مركز إعدادات العناية عن `res.config.settings` وعدم منح مسؤول التهيئة
  وصولًا إلى إعدادات Odoo التقنية أو الاعتماد على `base_setup`.
- استبدال حالة `setup_completed` العامة بملف دائم وفريد لكل شركة.
- إزالة منح مدير المركز صلاحية `base.group_system` وفصل الأدوار.
- إضافة مجموعة أساس للقراءة المشتركة حتى لا يرث الفني أو المحاسب دور
  «موظف الاستقبال»؛ الأدوار الوظيفية مستقلة وتلتقي فقط في الحد الأدنى المشترك.
- إضافة ACL وrecord rules للشركات المسموحة.
- إيقاف وحذف ويزارد أجزاء قديم كان يستدعي نماذج غير معرفة ويكرر المسار المتشعب.
- إزالة ملفات النسخ والتجربة غير المحملة التي كانت تربك المصدر.

## القرارات المعمارية

- ملف `wof.company.profile` هو مصدر حالة التهيئة، وليس `TransientModel`.
- أزرار Odoo تستدعي عمليات نموذجية مشتركة قابلة لإعادة الاستخدام من API.
- الأكواد التقنية و`public_uuid` هي العقد المستقر؛ الأسماء العربية للعرض والترجمة.
- القوالب تطبق بطريقة upsert حسب أكواد الشركة، لذلك إعادة التطبيق لا تكرر البيانات.
- سجل التدقيق append-only ويحفظ المستخدم والشركة والمصدر والحدث.
- لا توجد controllers قبل اعتماد OAuth2/OIDC ومراجعة الأمان.
- pre-migration يولد UUID مستقلًا لكل سجل قديم، ويملأ الأكواد الناقصة بصيغة
  `LEGACY-*` قبل فرض القيود الجديدة.
- pre-init يهيئ UUID فريدًا لسجلات الشركة والمستخدم والمنتج الموجودة عند أول
  تثبيت، قبل إنشاء قيد uniqueness، ويصنف المنتجات السابقة بمصدر `import`.

## الفحوص

- تجميع Python.
- تحليل كل XML المحمل.
- كشف تكرار external IDs وترتيب المراجع المحلية.
- مطابقة مراجع ACL مع النماذج المعرفة.
- كشف العلاقات المخصصة التي تشير إلى نماذج غير معرفة.
- فحص عدم وجود `setup_completed` أو منح `base.group_system` في التنفيذ.

## إصلاحات مراجعة الاعتماد النهائية

- فرض UUID من الخادم ومنع تغييره أو تمريره من RPC.
- منع تزوير `operation_source`؛ المصدر الحالي يفرض `odoo_web` حتى تنفيذ
  طبقة التكامل الآمنة، وفصل مصدر الحدث الحالي عن مصدر إنشاء السجل.
- إضافة UUID وأكواد تقنية لمراجع السيارات والدرجات والمنتجات الخارجية.
- إضافة pre-init للسجلات الأساسية وpre-migration للسجلات القديمة والأكواد
  وطرازات السيارات التي بلا مصنع، مع وسم السجلات السابقة بمصدر `import`.
- السماح للمدير بقراءة لوحة الجاهزية وفتح الإعدادات المرتبطة، مع حصر تعديل
  ملف التهيئة بمسؤول التهيئة.
- إصلاح إنشاء السعر والعمولة من القوائم العامة بإظهار علاقة الجزء الإلزامية.
- إضافة شاشات الشركات المصنعة وخيارات الأجزاء وتوثيق جميع الشاشات المحملة.
- تحسين مؤشر الخطوات على الجوال ليصبح أفقيًا قابلًا للتمرير.
- إزالة الكود القديم المعلق وتنظيف أسماء النماذج والشاشات والنصوص المساعدة.
- نقل حقل العملة إلى مسودة الخدمة التي تحمل حقول السعر والعمولة، والتحقق ساكنًا
  من كل حقل `Monetary`.
- حماية حقول دورة حياة التهيئة وإعداداتها من الكتابة العامة، وربط كل خدمة
  مفعلة بقالب مطابق على مستوى النموذج.
- منع حذف مسودات الأحجام والخدمات؛ التعطيل هو المسار الآمن، وإعادة تطبيق
  التهيئة تؤرشف الأحجام والخدمات والأفلام التي أُلغي تفعيلها وتعيد تنشيطها
  دون إنشاء نسخة مكررة.
- تحديث العمولة إلى الصفر عند اختياره بدل إبقاء قيمة سابقة، والتحقق من أن
  الجزء المجاني لا يحمل سعرًا أو ضريبة.
- إضافة فاحص ساكن قابل لإعادة التشغيل في `tools/static_validation.py`.

## قيد التحقق

بيئة العمل الحالية لا تحتوي تشغيل Odoo 17 أو PostgreSQL، لذلك يلزم قبل الإنتاج
تثبيت فعلي على قاعدة اختبار، وترقية من نسخة بيانات ممثلة، وتجربة شركتين وأدوارهما.
فحوص OpenAPI الحالية بنيوية ساكنة؛ مكتبتا PyYAML وOpenAPI validator غير
متاحتين في البيئة الحالية، ويلزم validator وcontract tests عند توفر بيئة
التكامل.

## نتيجة الجولة النهائية — 2026-07-30

- `STATIC_VALIDATION_PASS`: ‏19 ملف Python، 16 ملف XML محمل، 106 معرفات
  خارجية، 39 صف ACL، 28 زر model، 13 دليل شاشة و6 عمليات OpenAPI مخططة.
- `PYTHON_COMPILE_PASS`.
- `LXML_AND_XPATH_PASS`: تحليل 16 ملف XML وتجميع تعبيري XPath.
- لا توجد مراجع تنفيذية إلى `base.group_system` أو `res.config.settings` أو
  `setup_completed`، والاستعمال الوحيد لـ`sudo` محصور في إدراج سجل التدقيق.
- لا يمكن إصدار اعتماد تشغيل أو ترقية قاعدة بيانات من هذه البيئة لغياب Odoo
  وPostgreSQL و`odoo-bin`.
