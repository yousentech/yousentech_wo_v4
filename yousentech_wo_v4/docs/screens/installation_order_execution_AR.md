# تنفيذ أمر التركيب والمواد

## الهدف والمستخدمون

واجهة تشغيل مبسطة للفني والمشرف: تعيين فني لكل خدمة، تحديث الإنجاز، إضافة
ملاحظة وتسجيل المواد المستخدمة. تصميمها قابل للاستخدام على التابلت والجوال.

## الحقول والإجراءات

تقدم الأمر متوسط تقدم خطوط الخدمات. كل خدمة تحمل فني التنفيذ ونسبة 0–100
وملاحظة. المواد تحمل المنتج والكمية ووحدة القياس والخدمة المرتبطة ومن سجلها.
«بدء التنفيذ» ينقل `intake` إلى `in_progress`، و«إرسال لفحص الجودة» ينقل إلى
`quality`.

## خطوات الاستخدام

1. عيّن فنيًا واحدًا على الأقل للأمر؛ عند وجود فني واحد يوزعه الخادم تلقائيًا
   على الخدمات غير المسندة.
2. ابدأ التنفيذ.
3. حدّث تقدم كل خدمة وسجل المواد والملاحظات.
4. اجعل كل خدمة 100٪ وحدد فنيها.
5. أرسل الأمر لفحص الجودة.

## التحقق والأخطاء

- الفني يعدل الأوامر والخدمات المسندة إليه فقط؛ المشرف يملك الإشراف العام.
- تقدم الخدمة بين 0 و100 والكمية المستخدمة أكبر من صفر.
- لا تسجل المواد إن كان المخزون معطلًا في تهيئة الفرع.
- لا يصل الأمر للجودة مع خدمة ناقصة أو بلا فني.
- `stock_move_id` محمي؛ تسجيل المادة لا يعني صرفًا مخزنيًا فعليًا بعد.

## الصلاحيات والارتباطات

الفني والمشرف/المدير ينفذون. الاستقبال يقرأ التقدم. القسم مرتبط بالخدمات،
فحص الاستلام، صور بعد التنفيذ، ثم الجودة.

## الأثر على الفاتورة والمخزون والضمان

لا يغير التقدم المبلغ. المواد سجل تشغيلي ينتظر تكامل المخزون في المرحلة 4.
الفني والعمولة المهيأة أساس احتساب العمولات لاحقًا، ولا تنشأ مطالبة ضمان هنا.

## عقد التكامل مع Flutter

- العمليات المخططة: `start-execution`, `submit-quality`.
- المزامنة المستقبلية محدودة بخدمات الفني المسندة، `write_date` وcursor.
- تحديث النتيجة الحساسة سيقبل `Idempotency-Key` عند تنفيذ controller.
- الخادم هو صاحب صلاحية التقدم والإسناد والحالة، ويعيد
  `TECHNICIAN_NOT_ASSIGNED`, `EXECUTION_INCOMPLETE`, `INVENTORY_DISABLED`
  و`INVALID_STATE_TRANSITION` كأكواد ثابتة.
- لا توجد مزامنة offline أو API منفذة الآن.
