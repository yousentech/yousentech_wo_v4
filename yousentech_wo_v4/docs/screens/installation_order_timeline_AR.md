# السجل الزمني لأمر التركيب

## الهدف والمستخدمون

عرض من نفذ كل انتقال ومتى ومن أي مصدر، مع سبب الإلغاء أو تجاوز السعر. يقرأه
جميع مستخدمي نظام العناية ويستخدمه المشرف والمدير للمراجعة.

## الحقول والأحداث

الوقت، اسم الحدث، الحالة السابقة والجديدة، المستخدم، مصدر العملية والملاحظة.
الأكواد الثابتة تشمل `order.created`, `order.arrival_confirmed`,
`order.intake_completed`, `order.execution_started`, `order.sent_to_quality`,
`order.quality_rejected`, `order.quality_passed`, `order.delivered`,
`order.cancelled`, `order.price_overridden`.

## طريقة الاستخدام

افتح تبويب «السجل الزمني» ورتب الأحداث زمنيًا. راجع الملاحظة عند إعادة الجودة
أو الإلغاء، وطابق تجاوز السعر مع خط الخدمة وسبب الاعتماد في سجل التدقيق.
لا توجد أزرار إنشاء أو تعديل أو حذف.

## التحقق والأمان

ينشئ الخادم الأحداث بعد اجتياز ACL والشركة والدور والحالة. المستخدم لا يملك
ACL للإنشاء. يستخدم الكود `sudo` محدودًا فقط لإدراج صف append-only مبني خادميًا،
ولا يستخدم لقراءة الأمر أو تنفيذ انتقال. سجل `wof.audit.log` الموازي غير قابل
للتعديل أو الحذف أيضًا.

## الشاشات المرتبطة والأثر

السجل جزء من أمر التركيب ويغطي الخدمات والاستلام والتنفيذ والجودة والتسليم.
لا يغير الفاتورة أو المخزون أو الضمان؛ هو دليل تدقيق لها عند ربطها لاحقًا.

## عقد التكامل مع Flutter

- يعاد ملخص الأحداث ضمن قراءة الأمر أو endpoint أحداث مخطط لاحقًا.
- كل حدث يحمل UUID ومصدرًا موثوقًا وتوقيت UTC وكودًا machine-readable.
- Flutter لا يرسل `user_id`, `operation_source` أو `occurred_at`.
- لا يسمح API بتعديل/حذف حدث.
- أخطاء القراءة: `FORBIDDEN`, `ORDER_NOT_FOUND`; لا يعاد `details_json`
  الداخلي ولا stack trace.
