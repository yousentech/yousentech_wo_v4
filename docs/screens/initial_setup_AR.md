# شاشة التهيئة الأولى

## الهدف

تشغيل النظام لأول مرة دون تدخل الدعم. الشاشة موجّهة: سؤال واحد في كل خطوة،
ومعاينة مباشرة لأثر كل قرار، وألوان ثابتة المعنى.

## المستخدمون ومتى تستخدم

مسؤول تهيئة نظام العناية عند أول تشغيل، أو عند إعادة فتح التهيئة لتعديل الأساس.

## الخطوات والحقول

عمود جانبي بالخطوات وحالة كل خطوة، والمحتوى في الوسط، وشريط سفلي ثابت.

1. الأنشطة: تفعيل وتسمية الأنشطة وإضافة نشاط خاص.
2. أحجام السيارات: تفعيل وتسمية الأحجام وإضافة حجم بكود اختياري، مع معاينة أعمدة المصفوفة.
3. درجات اللون: تظهر فقط عند تفعيل العزل الحراري؛ طريقة الترقيم والدرجات المعتمدة.
4. التشغيل في خمس شاشات قصيرة:
   - بيانات أمر التركيب: لكل حقل إجباري أو اختياري أو مخفي.
     حالة حقل «الفني» تضبط أيضًا «الفني إجباري».
   - الضريبة والأسعار: تطبيق الضريبة والضريبة الافتراضية مع حسبة مثال، وسياسة التسعير.
   - الفوترة: يدويًا، أو تلقائيًا عند التأكيد، أو بعد اكتمال الدفع.
   - الخصومات: التفعيل والحد ونسبة إلزام السبب وطلب التجاوز والنطاق، مع شريط يوضح كل نسبة.
   - الفنيون والعمولة: تعدد الفنيين ووقت استحقاق العمولة.
5. المراجعة والتفعيل: النواقص مع زر «إصلاح»، والملخص، وما يُثبَّت بعد التفعيل.

دليل الألوان: أخضر مزرق مفعّل ومكتمل، برتقالي يحتاج قرارك، بنفسجي يُثبَّت بعد
التفعيل، أزرق توضيح ومعاينة.

## الأزرار وخطوات الاستخدام

كل تغيير يُحفظ فورًا. «التالي» و«السابق» أو الضغط على أي خطوة في العمود للتنقل.
«حفظ والمتابعة لاحقًا» يغلق النافذة، وتعود لنفس الخطوة عند الفتح. «تفعيل النظام»
لا يعمل حتى تكتمل النواقص.

## التحقق والأخطاء

- يلزم نشاط واحد وحجم واحد، ودرجة لون واحدة عند تفعيل العزل.
- الضريبة الافتراضية مطلوبة عند تطبيق الضريبة.
- نسب الخصم بين 0 و100.
- تظهر رسالة عربية تحدد النقص ولا يتم التفعيل جزئيًا.
- لا يمكن ضبط الحالة `ready` مباشرة عبر RPC؛ التفعيل يمر بعملية الجاهزية نفسها.
- بعد أول تطبيق لا يتغير الكود التقني للحجم، وطريقة ترقيم درجات اللون مثبتة بعد
  التفعيل، لحماية عقود Flutter والبيانات المرتبطة.

## الصلاحيات

متاحة لمجموعة `group_wo_settings` فقط، مع record rule للشركات المسموحة. كل عملية
تتحقق من الصلاحية في الخادم.

## الشاشات المرتبطة والأثر

التفعيل ينشئ الأنشطة والأحجام ودرجات اللون الرسمية فقط. الأفلام والخدمات وأسعارها
تُضاف بعدها من بوابة الأنشطة ومصفوفة التسعير والعمولة. لا تنشئ فاتورة أو حركة مخزون.

## مثال

عزل حراري فقط، أربعة أحجام، ترقيم تسلسلي 00–04، الضريبة 15%، فوترة يدوية، خصم حتى
10% وسبب إلزامي من 5%، والعمولة عند إنجاز الأمر.

## عقد التكامل مع Flutter

- العمليات الخادمية: `wof_flow_load` و`wof_flow_apply(op, payload)` على
  `wof.company.profile`، وتعيد لقطة JSON كاملة بعد كل تغيير. تستخدمها واجهة Odoo
  حاليًا، وأي REST مستقبلي يعتمد `public_uuid` وأكواد الحقول لا المعرفات الداخلية.
- العمليات: `activity`, `activity_add`, `size`, `size_add`, `tint_method`, `shade`,
  `field`, `set`, `invoice`, `goto`, `activate`.
- الصلاحية: مسؤول التهيئة والشركات الموجودة في `allowed_company_ids`.
- أخطاء متوقعة: `SETUP_ACTIVITY_REQUIRED`, `SETUP_SIZE_REQUIRED`,
  `SETUP_TINT_METHOD_REQUIRED`, `SETUP_TINT_SHADE_REQUIRED`,
  `SETUP_OPERATION_TAX_REQUIRED`.
- التواريخ التي تعيدها عمليات النموذج موحدة UTC بصيغة ISO-8601.
